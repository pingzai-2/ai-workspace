本文件是 AI / 开发代理进入 `4cp-simulator` 工程时必须遵守的中文规则入口。项目的完整构建、运行、架构、协议和测试说明统一维护在 [README.md](README.md)。开始修改前必须完整阅读 README。

## 工程边界

- 当前工程是 **Windows 版 4CP / 全热新风 Modbus RTU 设备模拟器**，用于替代真实 RS485 从机。
- 当前协议基线是仓库内最新 **v1.22**。
- CRC16 使用标准 Modbus RTU 线路顺序：低字节在前、高字节在后。
- 默认 4CP 地址为 `0xD1`，全热新风地址为 `0xC1`，默认串口参数为 `9600 / 8N1`。
- 当前已实现功能码为 `02H`、`03H`、`04H`、`06H`、`10H`。
- 不根据已废弃的文档内容恢复过时的寄存器地址和命令。

## 架构约束

- 保持“进程 + 调度器”解耦：一个进程独占一路 COM，并明确选择一个通信调度器。
- 多路串口通过多个并列进程实现；不得把多路串口硬塞进单个设备实例。
- 保持通信与数据处理分离：libmodbus 通信线程只负责收包、校验、同步数据镜像和立即应答，数据线程负责周期更新。
- `external/libmodbus 3.1.2` 与 `external/libhv 1.3.4` 必须和后端保持同一 SDK 母版；平台差异只放在构建适配层。模拟器当前不链接 libhv。
- 当前调度器是 `modbus-slave-response`。新增主机或从机策略时，应新增调度器类型、工厂映射和独立实现，不在 `main.cpp` 中堆业务分支。
- 协议常量集中维护在 `include/4CP_Protocol.h`，不要在多个模块重复写裸地址。

## 修改要求

- 先确认当前源码和 v1.22 协议，再修改实现；文档不能替代代码验证。
- 修改保持小范围、边界清楚、便于测试，不为暂时没有的需求提前增加复杂抽象。
- 新增或修改寄存器时，同时检查初始化、读写处理、异常响应、模拟更新和测试客户端。
- 不把串口、Visual Studio 或 CMake 的本机绝对路径写进 C++ 业务源码；构建路径只放在脚本顶部配置区。
- 不随意修改或删除历史辅助脚本；若入口已过时，应在 README 明确其适用边界。
