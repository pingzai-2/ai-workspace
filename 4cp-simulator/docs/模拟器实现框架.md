# 模拟器实现框架

## 1. 文档定位

本模拟器是 Windows 上运行的 Modbus RTU 设备替身。它通过真实串口接入 RS485 总线，后端主站不应依赖“这是模拟器”这一事实。

当前只实现 Windows 从机模拟。进程、调度器和数据镜像已经分层，后续可以新增其他主机或从机调度器，但不在当前通信线程里混合角色。

## 2. 总体结构

```text
ProcessSupervisor
  ├─ 进程 1：COM 1 + 地址 1 + 调度器 1
  ├─ 进程 2：COM 2 + 地址 2 + 调度器 2
  └─ ……

单个模拟器进程
  └─ CommunicationScheduler
       └─ ModbusSlaveScheduler
            ├─ SimulatorCore          串口收包、校验和应答
            ├─ DeviceSimulator        统一寄存器/位镜像
            └─ DataProcessingLoop     周期模拟数据
```

一个进程独占一路 COM。进程定义只描述名称、串口、波特率、设备地址和所选调度器；进程管理器只负责创建、等待和退出转发。

## 3. 统一设备镜像

每台模拟设备只有一份受锁保护的数据源：

```text
保持寄存器  0x1000..0x1076
输入寄存器  0x2000..0x203B
离散输入    从 0x3000 开始的位区
```

通信线程读这份镜像，写请求也回写同一份镜像；数据线程更新传感器、运行数据、故障和通知时仍操作同一份镜像。不得再维护一份独立 libmodbus mapping 作为业务真值，否则通信写入和随机更新会互相丢失。

设备镜像锁只保护定长内存读写。串口等待、日志输出和慢处理不得持有镜像锁。

## 4. 通信与数据处理分离

### 4.1 通信线程

单帧处理顺序：

```text
libmodbus 接收并校验请求
  -> 按设备地址选择镜像
  -> 复制本次应答需要的数据到 libmodbus mapping
  -> 校验功能码、地址、数量和写入条件
  -> 立即发送正常或异常响应
  -> 已接受的 06H/10H 请求回写统一设备镜像
  -> 记录汇总日志和处理耗时
```

写响应由请求本身确定，因此先完成应答，再把已校验写值应用到统一镜像。通信线程串行处理请求；下一帧到来前镜像已经完成更新，所以后端随后的确认读可以读到写入结果。

无效帧先 `flush` 后丢弃。可恢复的超时、CRC 或帧错误不杀死进程；连续不可恢复串口错误达到上限后主动退出，不能保持“进程还在但串口已经失效”的假活状态。

### 4.2 数据线程

独立数据线程周期调用 `UpdateAllDevices`：

- 可以变化温湿度、PM2.5、CO2、风机状态、故障和维护通知；
- 可以出现“有故障 -> 换一组故障 -> 无故障 -> 再出现”的动态过程；
- 不覆盖 `1001H/1002H/1003H` 三个模块控制开关；
- 收到通信写命令后，三个开关按写值和互斥规则改变并可读回。

随机数据用于观察链路是否持续通信，不承担设备控制逻辑。随机更新与通信写入都通过同一个镜像锁，因此不会产生撕裂的半组寄存器。

## 5. 协议行为

当前功能码：

| 功能码 | 行为 |
|---|---|
| `02H` | 读取离散输入 |
| `03H` | 读取保持寄存器 |
| `04H` | 读取输入寄存器 |
| `06H` | 写单个保持寄存器 |
| `10H` | 写多个保持寄存器 |

统一限制：

- 默认 `9600 / 8N1`；4CP 默认地址 `0xD1`，全热新风默认地址 `0xC1`。
- 单次读取或写入最多 50 个寄存器。
- RTU CRC 使用标准 Modbus 线路顺序：低字节在前、高字节在后。
- 非本机地址不处理；非法功能码、地址、数量或数据返回 Modbus 异常。
- 保持寄存器联动和写入条件由设备镜像策略校验，不由通信框架猜测。

已确认的模块规则：

- `1000H` 可直接写：写 `1` 为一键开启（模块状态保持），写 `0` 为整机关机（`1001H/1002H/1003H` 联动清零）；模块写仍会自动派生 `1000H`。
- 新风 `1001H` 与调湿 `1003H` 可以同时开启。
- 超净 `1002H` 与新风、调湿互斥。
- `1007H/1008H` 仅在新风模块 `1001H` 开启时可写。
- `102BH/102CH` 高低压开关、`1038H..103EH` 风量与阀门设定仅在厂测模式（`1030H=100`）时可写。

## 6. 多进程和调度器扩展

单进程入口：

```powershell
.\build\windows\Release\4CP_Simulator.exe -p COM3 -b 9600 -a 0xD1 -s modbus-slave-response
```

多进程入口：

```powershell
.\build\windows\Release\4CP_Simulator.exe `
  --process process-1 COM10 9600 0xD1 modbus-slave-response `
  --process process-2 COM11 9600 0xC1 modbus-slave-response
```

增加新调度器时：

1. 实现 `CommunicationScheduler` 接口。
2. 在调度器工厂注册新类型。
3. 在进程定义中选择新类型。
4. 不修改 `ProcessSupervisor` 的进程管理职责。
5. 不把主站轮询逻辑塞进当前从机应答循环。

## 7. Windows 构建和运行

两套离线构建入口都保留：

| 入口 | 环境 | 默认联调串口/产物 |
|---|---|---|
| `build_simple.bat` | 使用当前命令行可发现的 VS/CMake | 历史联调示例 `COM10`，产物在 `build\Release` |
| `build_windows.bat` | 顶部配置 CMake 和 VS 路径 | `run_windows.ps1` 默认 `COM3`，产物在 `build\windows\Release` |

推荐执行：

```powershell
.\build_windows.bat
.\run_windows.ps1
```

`run_windows.ps1` 前台运行，日志统一写入 `logs\run_windows.log`。关闭前台进程后日志文件才会解除占用。

构建时使用仓库内 `external/libmodbus 3.1.2`，不访问网络。仓库归档的 `libhv 1.3.4` 与后端同源，但当前模拟器不构建、不链接该库。

## 8. 测试边界

本机协议测试覆盖：

- 功能码、地址范围和 50 寄存器上限；
- 06H/10H 写入后从同一镜像读回；
- 模块互斥和 `1006H..1008H` 条件；
- 随机数据不会覆盖模块控制开关；
- 故障和通知可以动态变化。

Windows 构建成功只证明产物可生成。真实通信还必须用两端 COM 或 USB-RS485 链路验证请求、响应、超时、断线和进程退出行为。
