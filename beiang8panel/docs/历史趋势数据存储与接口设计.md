# 历史趋势数据存储与接口设计

> 版本:v1.1(2026-09-04;实现于后端 v1.4.0 并已上板实测。样本记录实为 18 字节(9×2B),修正初稿"20 字节"笔误)
> 需求:后端存储室内/外温度、湿度、PM2.5、CO₂ 历史数据,前端历史趋势页面进入时拉取展示。
> UI 参考:四指标(温/湿/PM2.5/CO₂)× 室内外双曲线,按日(12 点 ×2h)/按周(7 天)/按月(当月至今天)。

---

## 1. 数据源(协议 v1.22 输入寄存器)

数据已在现有周期轮询链路(1s 整块 04H 读)中解析进 `DataManager` 缓存,**采样器只读缓存、不发串口请求**:

| 寄存器 | 含义 | 原始格式 | 语义值 |
|---|---|---|---|
| 200DH | RA1(室内)温度 | int16,实际×10 | ℃,1 位小数 |
| 200EH | RA1(室内)湿度 | uint16 | %RH,0-100 整数 |
| 200FH | RA1(室内)PM2.5 | uint16 | µg/m³,0-999 |
| 2010H | RA1(室内)CO₂ | uint16 | ppm,0-9999 |
| 2011H | OA(室外)温度 | int16,实际×10 | ℃ |
| 2012H | OA(室外)湿度 | uint16 | %RH |
| 2013H | OA(室外)PM2.5 | uint16 | µg/m³ |
| 2014H | OA(室外)CO₂ | uint16 | ppm |

解析代码现状:`BeiAng4CPGateway.cpp` `parseRawDeviceData()` 已映射到 `getRA1Sensor()/getOASensor()`(inputRegs[13..20]),并随 `publishModbusSnapshot` 进入 `m_environmentData` 与寄存器缓存。

## 2. 总体架构与数据流

```
4CP ──RTU── DataAcquisitionModule(1s 轮询)
                │ publishModbusSnapshot()
                ▼
        DataManager 寄存器缓存/EnvironmentData(内存,带新鲜度)
                │ 定时采样(默认 10min,对齐整十分钟)
                ▼
        HistoryRecorder(新模块,独立线程)
                │ 追加写
                ▼
   /mnt/UDISK/beiang8panel/history/samples-YYYYMMDD.bin(按天分文件)
                │ HTTP 请求时读文件聚合(单次 ≤31 文件 ≈140KB,ms 级)
                ▼
        GET /api/history/trend ──▶ Flutter 历史趋势页(DashboardData 趋势字段)
```

设计原则:
- **采样与查询彻底解耦**:采样线程只管对齐时钟追加记录;聚合在 HTTP 请求时现算。日文件极小(约 2.6KB/天),无需预聚合/数据库,断电损坏面最小。
- **不碰串口**:沿用"读路径走缓存"的既有约定,采样失败只影响当次样本。
- **前端形状优先**:接口返回桶序列 + 显式时间戳,点数与前端 `DashboardData` 已有字段一一对齐(日 12 / 周 7 / 月 N)。

## 3. 存储方案

### 3.1 目录与文件

```
/mnt/UDISK/beiang8panel/history/
    samples-20260903.bin
    samples-20260904.bin      ← 当天文件,追加写
```

选 `/mnt/UDISK/beiang8panel/` 的理由:与 logs/、ota/、radar_status.json 同区,是已验证开机可写、断电不丢的分区(rootfs 开机只读,不可放 rootfs)。

### 3.2 文件格式(定长二进制,小端)

**文件头 16 字节:**

| 偏移 | 长度 | 字段 | 值 |
|---|---|---|---|
| 0 | 4 | magic | `B8PH` |
| 4 | 2 | version | 1 |
| 6 | 2 | recordSize | 20 |
| 8 | 4 | date | YYYYMMDD(如 20260904) |
| 12 | 4 | reserved | 0 |

**样本记录 18 字节(9×2B):**

```cpp
#pragma pack(push, 1)
struct HistorySampleRecord {          // 18 字节,全部存协议原始值,无浮点损耗
    uint16_t minuteOfDay;   // 当日本地时间分钟数 0..1439(去重键)
    int16_t  raTempX10;     // 室内温度 ×10(200DH 原值)
    uint16_t raHumidity;    // 室内湿度   (200EH 原值)
    uint16_t raPm25;        // 室内 PM2.5(200FH 原值)
    uint16_t raCo2;         // 室内 CO₂  (2010H 原值)
    int16_t  oaTempX10;     // 室外温度 ×10(2011H 原值)
    uint16_t oaHumidity;    // 室外湿度   (2012H 原值)
    uint16_t oaPm25;        // 室外 PM2.5(2013H 原值)
    uint16_t oaCo2;         // 室外 CO₂  (2014H 原值)
};
#pragma pack(pop)
```

样本数 = (文件大小 − 16) / 18;**启动/打开时若尾部有撕裂记录(大小除不尽 18)则截断到最近完整记录**——这是断电安全的全部所需。

### 3.3 采样策略

- **周期**:默认 600s,对齐墙钟整十分钟(x0:00/10/20/…),配置项可调。
- **采样条件**:输入缓存有效(inputValid)且 Modbus 通信新鲜(复用 `ModbusFreshnessTracker` 30s 窗口)。条件不满足直接跳过该分钟,留空桶,不写哨兵值。
- **去重**:同一 `minuteOfDay` 只写一条(NTP 对时回拨时丢弃重复);时钟前跳则照常按新分钟写。
- **跨天**:采样线程检测本地日期变化后切换新文件;重启后打开当天文件续写(尾部撕裂先截断),并把当天已存样本读入内存缓存供日视图聚合。

### 3.4 写入与寿命

- 当天文件保持 `O_APPEND` 句柄,每条 `write(18B) + fdatasync` 后即落盘:每天 144 次 18 字节小写,对 UDISK 磨损可忽略(现有 syslog 写入量远大于此)。
- **保留策略**:默认保留 370 天(覆盖"今年同月对比"),启动与每日跨天时清理超期文件。容量:18B×144×370 ≈ **0.96MB/年**,可忽略。

## 4. 聚合规则(查询时现算)

三种 range 与前端页面语义一一对应(UI 时钟 08:30 时日轴显示 10:00…08:00,即滚动窗口):

| range | 桶定义 | 点数 | 桶值 |
|---|---|---|---|
| `day` | 以"最近整 2 小时"为末桶起点,向前 12 个 2h 桶(滚动 24h;末桶为进行中,样本可能不满) | 12 | 桶内有效样本算术平均 |
| `week` | [今天−6 天 … 今天],本地自然日 | 7 | 当日全部有效样本平均 |
| `month` | 当月 1 号 … 今天(anchor 指定月的 1 号至 anchor 当日) | N=anchor 日号 | 当日全部有效样本平均 |

- **有效性过滤**(聚合前,按协议量程):湿度>100、PM2.5>999、CO₂>9999、\|温度\|>60.0℃ 的样本视为无效,仅从均值中剔除(不影响其他字段)。
- **输出精度**:温度 1 位小数(×10 原值即精确),湿度/PM2.5/CO₂ 均值四舍五入为整数(前端绘制即整数刻度)。
- **空桶输出 null**(JSON null),前端绘制为断点;整段无数据时数组全 null,HTTP 仍 200。
- 时间桶边界一律用**面板本地时间**(自然日语义),`timestamps` 返回 UTC epoch 秒,前端本地化格式化。

## 5. HTTP 接口

封装风格:**wrapped `{code, message, data}`**,与 `/api/runtime/snapshot` 等读接口及 `BasePage::buildSuccess` 一致(前端 `_unwrapData` 原生兼容)。路由注册在 `HttpServerBasedOnLibhv::registerRoutes()`,实现落在 `HistoryTrendPage`。

### 5.1 `GET /api/history/trend`(页面主接口)

**参数**

| 参数 | 必填 | 说明 |
|---|---|---|
| `range` | 是 | `day` / `week` / `month`(非法值返回 HTTP 400) |
| `date` | 否 | 锚点日期 `YYYY-MM-DD`,默认今天。v1 前端不传;预留历史回看 |

**响应示例(range=day,2026-09-04 08:30 请求,UTC+8)**

```json

  "message": "success",
  "data": {
    "range": "day",
    "intervalSeconds": 7200,
    "anchorDate": "2026-09-04",
    "timestamps": [1788400800, 1788408000, 1788415200, 1788422400, 1788429600,

      "humidity":    [52, 53, 54, 55, 55, 56, 55, 54, 53, 52, 51, 50],

      "temperature": [28.2, 27.6, 27.0, 26.5, 26.9, 28.4, 30.2, 31.8, 33.0, 33.6, 33.2, 32.5],
      "humidity":    [65, 67, 70, 72, 70, 62, 55, 48, 43, 40, 41, 44],
      "pm25":        [22, 21, 20, 20, 21, 23, 26, 28, 29, 28, 27, 26],
      "co2":         [420, 420, 419, 419, 420, 421, 421, 422, 422, 421, 421, 420]
    },
    "sampleCount": 132,
    "storageError": null

```

字段说明:
- `timestamps`:每桶起始 UTC epoch 秒;`day`=12 项(间隔 7200s)、`week`=7 项(间隔 86400s)、`month`=N 项。
- `indoor/outdoor` 各 4 数组与 `timestamps` 等长;**null=该桶无有效样本**(如 4CP 离线时段)。
- `outdoor.co2` 一并提供(2014H 存在);当前前端模型只消费室内 CO₂,属前向兼容,成本可忽略。
- `sampleCount`:聚合覆盖的原始样本数;`storageError`:UDISK 不可写等存储异常时为错误描述字符串且各数组为全 null(仍 200,页面优雅降级为空图)。

**错误**

| 场景 | HTTP | body |
|---|---|---|
| `range` 缺失/非法、`date` 格式错 | 400 | wrapped `{"code":400,"message":"..."}` |
| 其它内部异常 | 500 | 现有 `sendError` 模式 |

## 8. 前端对接映射(887t25901)

前端仅需在 `lib/services/beiang8panel_api.dart` 新增 `readHistoryTrend(String range)`(`_unwrapData` 已兼容 wrapped),按页面当前 range 拉取后写入 `DashboardData`(`copyWith`),无需改 UI:

| range | 写入字段(`lib/models/dashboard_data.dart:438-460`) |
|---|---|
| day | `dailyTemperatureIndoorC/OutdoorC`(12)、`dailyHumidityIndoor/OutdoorPercent`、`dailyPm25Indoor/Outdoor`、`dailyCo2Ppm`(室内) |
| week | `weeklyTemperature*`、`weeklyHumidity*`、`weeklyPm25*`、`weeklyCo2Ppm`(各 7) |
| month | `monthlyTemperature*`、`monthlyHumidity*`、`monthlyPm25*`、`monthlyCo2Ppm`(取前 N)+ `monthlyTrendYear/Month` ← `anchorDate` |

null 桶由前端按现有断线绘制策略处理。刷新时机已登记于 `dashboard_page_refresh_policy.dart:128-154`(`DashboardPageScope.history`),进入历史页触发一次即可,无需轮询。

## 9. 边界情况清单

| 场景 | 行为 |
|---|---|
| 断电/崩溃 | 尾部撕裂记录启动时截断,最多丢最后 ≤10 分钟样本 |
| 4CP 离线/缓存不新鲜 | 跳过采样,对应桶 null;页面显示断点 |
| UDISK 不可写/丢失 | Recorder 自禁用并打 error 日志,API 200 + 全 null + `storageError`;其余接口不受影响 |
| NTP/对时跳变 | 同 `minuteOfDay` 去重;日期跳变触发跨天切文件 |
| 重启当天 | 续写当天文件,内存缓存从文件重载,当日数据不丢 |
| 恢复出厂 | (可选)清空 history 目录——挂接现有恢复出厂流程,未挂接则按保留期自然过期 |
