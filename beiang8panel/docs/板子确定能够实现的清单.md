# 板子确定能够实现的清单

> 母版实现版：2026-08-23
> 当前依据：`4CP-8寸控制面板软件开发说明-V1.3.1-0810.xlsx`、R818/R528 已知系统接口、BeiAng8Panel 与 8 寸 App 当前源码。
> 本文记录非 TTY 的本机/网络能力。代码已有接口不等于真实板端已经验收。

## 1. 范围

本清单只处理控制面板本机和网络能力：

```text
Flutter / 外部控制器
          |
       统一 HTTP API
          |
   DataManager 状态快照
          |
   本机硬件线程 + Wi-Fi 管理线程
      |                         |
本机硬件/系统接口       Wi-Fi 系统程序
```

Modbus TTY 的 1000H/2000H/3000H 数据不放在这里，见《协议确定能够实现的清单.md》。

## 2. 已确定的运行模型

1. TTY 通信线程和本机设备线程相互独立，不能让 Wi-Fi 扫描、天气请求或 sysfs 操作阻塞 Modbus 脉搏。
2. HTTP 线程只投递本机命令、读取状态快照，不直接执行可能耗时的系统命令。
3. 本机线程周期采集温湿度、序列号、亮度、雷达状态等数据，并更新 DataManager。
4. Flutter 继续约每 2 秒拉取统一运行快照，不直接读 sysfs、状态文件或执行系统命令。
5. 本机命令的 HTTP 返回 `accepted` 只表示进入队列，不表示硬件动作完成。
6. `pending / success / error / state` 由后端状态快照表达过程；Flutter 下一轮轮询显示连接中、成功或失败。
7. 数据暂时只保存在现有 DataManager 内存快照中，不新增数据库或 JSON 落盘机制。
8. `/api/runtime/snapshot` 一次返回同代协议、环境、本机能力和有效标志；该 GET 不现场执行 sysfs、状态文件、TTY 或外网请求。
9. Modbus 缓存新鲜度只返回 `dataFresh` 布尔值，不返回缓存时间；后端仅用进程内单调时钟判断。任意一次真实的 485 读事务或写事务成功都立即重新计时；串口仅打开成功、命令仅入队、解析线程仅发布旧缓存都不能清零。自最后一次成功通信起未满 30 秒时为 `true`，达到 30 秒即返回 `false`，避免依赖板端可能错误的系统时间。
10. Flutter 分开表达“后端不可达”和“设备数据陈旧”，两种情况都保留最后一次有效业务值。
11. 本机读取和写入都采用轻量、按接口契约处理：不识别平台或板型，不猜测未知节点，不修改权限，不做强制预读或通用能力推断。

当前后端有两条非 TTY 工作线程：`LocalDeviceModule` 按 1 秒周期采集并处理亮度、AQI 指示灯等本机硬件命令；`WifiManager` 独立执行 Wi-Fi 扫描、连接、断开和状态查询。网络天气后续应保持为非 TTY 能力，但不要阻塞这两条快路径。

### 2.1 TTY、本机设备与外部网络服务的隔离

当前三类能力的真实隔离程度如下：

```text
TTY                 完整分离
本机设备            完整分离
Wi-Fi 系统操作       完整分离
天气/IP外部网络服务  逻辑分离，但线程和缓存模型尚未完全分离
```

- TTY 由 Modbus 通信调度器独占；周期读取只采集原始数据，另一处理线程解析并发布快照。
- 本机设备由 `LocalDeviceModule` 处理；sysfs、状态文件和本机命令不进入 TTY 调度器。
- Wi-Fi 由 `WifiManager` 独立处理；HTTP 只入队，工作线程执行固定系统程序并发布过程快照，不阻塞 TTY 或本机硬件采集。
- 天气、公网 IP 和定位不访问 TTY，也不阻塞本机设备线程；但当前由 HTTP 请求处理线程同步执行 curl 查询，命中 TTL 缓存时才能立即返回。外网请求较慢时会占用一个 HTTP 工作线程。
- 当前统一运行快照包含 TTY 和本机设备缓存，天气/IP 仍使用独立接口，尚未纳入同一快照。

后续母版的目标结构为：

```text
独立网络服务任务
  -> 按策略查询天气/IP/定位
  -> 发布 NetworkData 内存缓存

HTTP
  -> 只读 NetworkData 缓存
  -> 立即返回
```

该收口只改变外部网络服务的执行与缓存方式，不改变已经分离的 TTY 和本机设备模型。未实现独立网络任务前，不得将其描述为已完成。

### 3.1 屏幕、待机与启动时序

PRD 中可以确定的目标动作：

1. 物理键短按执行息屏/点亮；长按 3 秒执行整机重启。
2. 点亮后显示待机页，触摸待机页任意位置进入首页。
3. 人感雷达检测到人员接近时点亮待机页，而不是直接进入首页。
4. 启动/重启期间物理 AQI 指示灯绿色呼吸，间隔约 1 秒；开机动画约 3 秒，最后一帧保持并显示加载图标。
5. 设置页提供 15/30/45/60 秒的息屏时间选择。

PRD 同时存在两个尚未能合并的时序描述：

- 待机页章节写“开机后无操作或轻触唤醒后的首个画面”；
- 现有样板和既有讨论采用“约30秒无操作进入待机，再约30秒息屏”的两阶段模型；
- 设置页只写“息屏时间 15/30/45/60 秒”，没有说明它控制进入待机、待机到息屏，还是总无操作时间。

因此初版保留当前 App 空闲模型和后端休眠命令，不重写时序。等客户确认一个时间轴后，再统一 App 计时、雷达唤醒和板端休眠动作。

### 3.2 雷达

- 默认开启。
- 传感器章节写“接近 1 米内点亮待机页”。
- 设置章节又允许选择 1/2/3 米，前置条件是雷达开启。
- 真实状态仍来自雷达进程/状态文件，开关命令只表达操作过程；不能用“已写命令”伪造人员已接近。

这两处并非完全等价：1 米可能是默认值，也可能是固定产品要求。未确认前，后端保存开关、配置距离和原始检测数据，但不自行确定距离阈值、去抖时间和接近/离开滞回。

### 3.3 AQI 指示灯

物理 9 路 RGB 的目标状态至少分为三类：

| 状态 | PRD目标 |
|---|---|
| 启动/重启 | 绿色呼吸，约1秒间隔 |
| 室内空气质量 | 优=绿、良=黄绿、中度污染=黄、重度污染=红；默认开启，设置页可关闭 |
| 严重故障 | 红色呼吸；严重故障报警默认开启 |

三类状态必须有仲裁关系；“严重故障 > 启动状态 > 正常空气质量”可以作为候选，但 PRD 没有明写同时发生时的优先级，也未提供严重故障 bit 清单、未说明用户关闭空气质量指示灯后是否仍必须显示严重故障。初版只把三类状态分开建模，不复用 App PM2.5 的紫色 L4，也不在静态 RGB 接口上伪造呼吸能力。

### 3.4 Wi-Fi、天气和联网状态

- Wi-Fi 关闭时不显示网络图标。
- 开启后支持扫描、选择网络、输入密码、连接和断开。
- 配网过程中图标约 0.5 秒闪烁，连接完成后常亮；失败应进入明确失败状态，不能保持“连接中”假活。
- 联网后取得区域和天气；天气约每小时更新，获取失败显示占位符，而不是把旧值改成 0。
- Wi-Fi 过程状态和天气数据都进入后端缓存，HTTP 只读缓存；网络调用不能进入 TTY 线程。
- 已保存的 Wi-Fi 开关是连接策略：App 启动、后端恢复和开关重新开启各形成一个边沿事件；开启时按最多 10 个最近成功凭据的 LRU 顺序尝试一轮，关闭时无论真实还是离线测试模式都执行一次关闭，不在每次快照轮询中重复发送。
- 普通“断开”只断当前连接，保持 Wi-Fi 开关、扫描列表和凭据，仍可进入网络详情页重新扫描/连接；同一后端在线周期内不因未连接快照立即自动重连。
- 网络详情页进入立即扫描一次，停留期间每 10 秒扫描一次；扫描按 SSID 去重、信号排序并最多显示 20 个。连接、断开等用户操作优先于扫描，离开页面停止扫描定时器。
- 后端不可达时冻结最后一次有效扫描列表；从未取得列表则为空。后端恢复后重新服从真实扫描和连接状态。
- 单个连接事务总期限为 20 秒，连接命令与结果确认共享该期限；手动连接立即抢占正在进行的自动连接。手动失败或超时后，从被打断的 LRU 项重新开始完整 20 秒，该项失败后才进入下一项；手动成功则结束本轮自动连接。
- 返回页面只停止页面扫描和等待显示，不取消已由后端接受的连接；后台若随后连接成功，仍由全局聚合快照确认并保存凭据。只有明确选择另一个 SSID、普通断开或关闭开关才终止当前连接事务。

当前 R818 Wi-Fi 系统适配已按已确认命令接入 `/usr/bin/emc6069_wifid`，并与本机硬件线程、TTY 线程分离。状态集合为 `disabled / idle / scanning / connecting / connected / disconnecting / failed`。连接请求的空密码仅用于真实开放网络；离线 UI 联调仍只接受约定测试密码，且不在输入框预填。R528 的命令可用性和 R818 长时稳定性仍需实机验收。

Wi-Fi 连接成功后的系统网络校时/RTC 同步属于板端驱动或系统服务能力；本轮 UI 不增加时间同步入口，也不把该过程塞进 Wi-Fi 连接 HTTP 请求。

### 3.5 设置与工程数据的归属

| 设置项 | 数据归属 | 当前边界 |
|---|---|---|
| 亮度 | 本机屏幕能力 | 有后端路径，需两种板型实机验收 |
| 语言、指标优先级、息屏时间 | App/本机产品配置 | 不进入Modbus；持久化位置后续统一 |
| 雷达、蜂鸣器、AQI灯 | 本机硬件能力 | 走本机命令队列；雷达读取状态文件，AQI 只认写调用结果，蜂鸣器等待适配 |
| Wi-Fi | 本机系统网络 | 过程型命令，必须发布扫描/连接/失败状态 |
| 服务电话、工程密码 | 本机工程配置 | 不从外部设备寄存器取得 |
| 4CP设备地址、风机档位、压缩机/阀门参数 | 外部设备工程参数 | 属于Modbus危险/工程写入，见协议清单 |
| OTA | 控制屏平台能力 | 独立高风险流程，不塞入普通设置保存 |

PRD 中 RS485 有两种说法：默认值页写设置中配置地址，设置页又写这里只展示连接状态、地址在工程模式配置。初版普通设置页只展示连接状态；修改地址继续视为工程操作，不允许普通开关直接停掉 TTY 主循环。

## 4. 确定的数据字典

本机能力也按“数据字典/填空”思想处理，不要求所有字段都来自 Modbus：

```text
LocalDeviceData
  wifi
    available / enabled / connected / state / targetSsid / connectedSsid
    ipAddress / rssi / scanResults / pending / success / error
  screen
    brightnessAvailable / minBrightness / maxBrightness / currentBrightness
    sleepStateAvailable / sleeping / pending / success / error
  temperatureHumidity
    temperatureAvailable / humidityAvailable / serialAvailable
    temperature / humidity / serial
  radar
    enable / online / distance / velocity / signal / gesture
    approach / depart / direction / pending / success / error
  aqiLed
    stateAvailable / level / color
    pending / success / error
  speaker
    available / enabled / volume / pending / success / error
  networkService
    locationAvailable / weatherAvailable / updating / error
    location / weather / forecast
```

原则：

1. 节点不存在、不可读或本次解析失败时，保留当前缓存基准，不用 `0`、空字符串或强制 `--` 覆盖。基准可以来自离线 JSON、普通默认值、持久化值、`--` 或上一次成功读取。
2. 没处理到的命令要返回明确的 `failed + error`，不能伪造成功。
3. 状态字段是实际采集结果；命令字段只表达过程，两者不能互相覆盖。
4. Flutter 只消费统一字段，不绑定具体 sysfs 路径和系统命令。
5. 对外快照不依赖系统时间戳判断新鲜度。内部如需超时和 TTL，只使用进程内单调时钟；对外发布 `available/online/dataFresh/state` 等状态，不把可能错误的系统时间当成有效性依据。
6. 每个读取适配器只检查自己的固定接口是否存在、当前可读，并按已确认格式解析；只有成功取得的字段才覆盖缓存，同组部分失败不清空其他字段。
7. 每个写入适配器只检查自己的固定接口是否存在、当前可写。失败保留上一次确认值；契约本身没有回读能力时，写成功采用请求值；接口为 `void` 或没有成功状态时，调用完成且未发生可检测异常就按成功处理；有明确回读能力时以实际值为准。
8. 不强制写前读取，不执行物理回滚写入，不执行 `chmod`、`sudo`，不使用通用逻辑推断范围、单位、板型或设备身份。有现成白名单时使用，否则由适配器固定自己的路径或命令。
9. 本机接口统一归类为只读采集器、只写执行器、本地数值调整器和过程型操作。数值调整器是可复用特例，不绑定亮度；只有同时确认安全读写能力后才能采用。

## 5. 首批确定的板端源码闭环

按风险和确定程度，建议顺序如下：

### 5.1 第一批：只读数据

1. GXHTC3 温度。
2. GXHTC3 湿度。
3. GXHTC3 序列号。
4. 当前屏幕亮度和最大亮度。
5. 雷达状态文件中的已确认字段。

当前结果：后端只在读取成功时覆盖相应缓存字段，因此能区分“真实 0”和“本次未取得新值”；读取失败保留当前基准。Flutter 已接收完整 `localDevice` 字典。屏幕量程和实际值已分别用于百分比换算与在线显示；其他尚未确认展示归属的工程数据不强行填入现有 UI 字段。

### 5.2 第二批：简单本机写入

1. 设置屏幕亮度。
2. 屏幕休眠/唤醒。
3. 雷达开关文件命令。
4. AQI 静态颜色。

当前结果：HTTP 先返回 accepted，本机工作线程稍后发布 success/error；命令入队不再写成硬件已成功。写失败保留上一次确认值；契约没有回读时，写成功采用请求值。亮度作为“本地数值调整器”，写后必须从本次写入的同一接口回读，回读失败保留旧确认值。8 寸 App 设置页已经接通亮度、AQI 指示灯和雷达开关；本机设置写入后复用统一的 350ms 可调、非重入补读。亮度展示真实回读值；屏幕休眠和 AQI 只写接口在系统调用成功后采用请求状态，AQI 不读取驱动节点反推物理灯态；失败都保留旧状态。扬声器没有满足产品语义和接口条件，暂不从 App 强接。

轻量接口契约覆盖当前所有已确认本机操作，不是亮度专用规则：

- 读取：屏幕亮度、GXHTC3 温度、湿度、序列号、雷达状态文件。
- 写入：屏幕亮度、屏幕休眠/唤醒、雷达命令文件、AQI 灯。
- Wi-Fi 已有 R818 固定系统程序适配，归入下一节的过程型操作；扬声器尚无已确认系统接口，继续明确返回未实现。

### 5.3 第三批：过程型操作

1. Wi-Fi 开关。
2. Wi-Fi 扫描。
3. Wi-Fi 连接/断开。
4. IP、网络状态、天气更新。

过程型操作采用：

```text
disabled / turning_on / idle / scanning / connecting /
connected / disconnecting / failed
```

例如连接 Wi-Fi：

```text
App POST connect
  -> 后端返回 accepted
  -> 状态变为 connecting
  -> WifiManager 异步执行固定系统程序
  -> 状态查询确认后变为 connected 或 failed
  -> App 下一次约2秒轮询看到结果
```

App 内的 Wi-Fi 管理器不依赖设置页生命周期。HTTP accepted 后的密码只暂存在本次内存意向中；聚合快照确认同一 SSID 已连接才更新唯一凭据。同名 SSID 新成功密码替换旧密码；连接失败不覆盖；断开不删除；“忘记”暂不实现。

板端网络守护进程可能在 App 下发连接命令前自行恢复历史网络。后端不区分该连接来自系统恢复、
App 自动连接还是用户手动连接，只按状态查询结果发布实际 SSID/IP；前端发现已经连接后不得重复
启动自己的 LRU 自动连接。刷写只读系统镜像也不必然清除可写分区或守护进程保存的网络凭据。

## 8. 本轮PRD覆盖与后续实现顺序

本轮已逐表核对物理按键、搭载传感器、AQI指示灯、扬声器、默认值、待机/首页、网络状态、设置和工程模式。能够直接确定的目标已经写入第3节；PRD自身冲突或缺少板端接口的项目已经列入B01..B21，没有用猜测补齐。

后续实现建议按风险和依赖顺序推进：

1. 先在R818/R528分别探测并记录亮度、休眠、GXHTC3、雷达、AQI、按键和扬声器真实节点/命令。
2. 屏幕亮度、AQI 指示灯和雷达开关的三端命令路径已经落地；继续在实机验收亮度/雷达回读和 AQI 9 路实际灯效。AQI 是明确的只写接口，聚合快照只表达写入结果和最后一次成功目标值。扬声器仍按“accepted、实际回读、unavailable”边界完成，不能拿设置意向冒充硬件状态。
3. 确定待机时间轴和雷达阈值后，再统一App空闲计时与板端休眠/唤醒。
4. 在 R818/R528 验收 Wi-Fi 适配，并将定位、天气继续收口为独立网络服务缓存。
5. 统一本机配置字典和持久化，再接语言、息屏时间、服务电话、工程密码等设置项。
6. OTA单独立项，完成包校验、版本判断、空间检查、断电恢复、失败回滚和重启验收后才开放入口。
